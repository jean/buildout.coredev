# Running buildout.coredev on Termux/Android

## Overview

These are the changes required to get `make install` and `make run` working on
Termux/Android. Some of these are committed to the repo; others must be
re-applied manually if the venv is recreated.

## Committed changes

### `stubs/robotframework-browser/`

`robotframework-browser` is a transitive test dependency (via
`plone.app.robotframework`) that requires a browser to function and cannot run
on Android. Its build also fails because `psutil` (one of its dependencies)
explicitly rejects the Android platform at build time.

A stub package is provided in `stubs/robotframework-browser/` that satisfies
the version requirement (19.10.1) without pulling in any dependencies.

It is referenced at the top of `requirements-test.txt`:

```
./stubs/robotframework-browser
```

### `stubs/grpcio/` and `stubs/opentelemetry-exporter-otlp-proto-grpc/`

`grpcio` requires compilation from C source. On Android/Termux (aarch64) this
fails because the NDK toolchain cannot successfully build the bundled c-ares
DNS library and related components.

`grpcio` is a transitive dependency via:

```
plone.observability[opentelemetry]
  → opentelemetry-exporter-otlp
    → opentelemetry-exporter-otlp-proto-grpc
      → grpcio
```

Two stubs are provided in `requirements-mxdev.txt` (listed before
`plone.observability[opentelemetry]` so pip/uv resolves them first):

- **`stubs/grpcio/`** — a version-only stub (`1.83.0`) with no C extension,
  satisfying the `grpcio>=1.66.2,<2.0.0` constraint from
  `opentelemetry-exporter-otlp-proto-grpc`.

- **`stubs/opentelemetry-exporter-otlp-proto-grpc/`** — version `1.44.0`,
  satisfies the exact-version pin from `opentelemetry-exporter-otlp`.  It
  provides the `opentelemetry.exporter.otlp.proto.grpc.trace_exporter`
  namespace and re-exports `OTLPSpanExporter` from the HTTP exporter
  (`opentelemetry-exporter-otlp-proto-http`) as a transparent drop-in.

Because the transport is HTTP instead of gRPC, use **port 4318** (HTTP/protobuf)
instead of the gRPC default 4317.

## OpenTelemetry instrumentation

`plone.observability[opentelemetry]` is listed in `requirements-mxdev.txt` and
provides a Paste Deploy filter for OTel tracing. Configure via environment
variables:

```
OTEL_SERVICE_NAME=plone
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318
```

> **Android/Termux note:** Use port **4318** (HTTP/protobuf), not 4317 (gRPC).
> The `stubs/opentelemetry-exporter-otlp-proto-grpc` stub re-routes the gRPC
> import path to the HTTP exporter so no native `grpcio` library is needed.

Tracing activates automatically when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.
The filter is wired into `instance/etc/zope.ini`. Note that this file is
generated by `make zope-instance` (via cookiecutter), so the filter entry
must be re-applied after regeneration. See the `[filter:otel]` section and
the `otel` entry in `[pipeline:main]`.

## Source checkouts for upstream fixes

Two packages required local fixes that live in `src/` as editable git checkouts.
They are registered in `mxsources.ini` and `mxcheckouts.ini` and are installed
with `pip install -e` during `make install`.

### `src/plone.base` (branch `3.x`)

`plone.observability` imports `boolean_value(value, *, default=False)` from
`plone.base.utils`, but this function was added after the `3.1.2` release
pinned in coredev.  The checkout of `3.x` already contains the function
(it appears as `3.1.3.dev0`).  No manual edit is required once the checkout
is installed.

### `src/plone.observability` (branch `main`)

Two fixes applied directly to the checkout:

1. **`src/plone/observability/otel/wsgi.py`** — `LoggingInstrumentor` is now
   called with `inject_trace_context=True` unconditionally in `make_filter`.
   Without this the `%(otelTraceID)s` / `%(otelSpanID)s` fields are missing
   from log records and every log line raises `ValueError`.

2. **`src/plone/observability/otel/provider.py`** — the gRPC
   `OTLPSpanExporter` import is satisfied by
   `stubs/opentelemetry-exporter-otlp-proto-grpc` which re-exports the HTTP
   exporter (no native `grpcio` needed).

Both fixes should be submitted as upstream PRs.

#### Namespace package note

`plone.observability` uses **hatchling** and does not emit a `nspkg.pth` file,
so the `plone` namespace package does not automatically pick up the editable
checkout.  A manual `nspkg.pth` is written to `.venv/lib/…/site-packages/`
during `make install` (see `Makefile`).  If the venv is recreated, re-run
`make install` to restore it.

## Manual patches (re-apply after venv recreation)

### Hard-link patches

Android filesystems do not support hard links, so Python does not expose
`os.link`. Two packages in the Zope stack assume `os.link` is always available.

### `.venv/lib/python3.13/site-packages/ZODB/blob.py`

Around line 950, change:

```python
link_or_copy = os.link
```

to:

```python
# Android/Termux: os.link (hard links) is not supported on Android filesystems.
# Fall back to shutil.copy which has a compatible (src, dst) signature.
link_or_copy = os.link if hasattr(os, 'link') else shutil.copy
```

### `.venv/lib/python3.13/site-packages/zope/sendmail/queue.py`

Add `import shutil` to the imports, then around line 47, change:

```python
_os_link = os.link
```

to:

```python
# Android/Termux: os.link (hard links) is not supported on Android filesystems.
# Fall back to shutil.copy which has a compatible (src, dst) signature.
_os_link = os.link if hasattr(os, 'link') else shutil.copy
```
